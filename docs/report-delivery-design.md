# 단어 오류 제보 전달 설계

현재 제보는 기기 안에 저장되고, 사용자가 직접 공유할 수 있다. 원본 라이브러리나 Google Sheets를 자동 수정하지 않는다. 앞으로는 **기기 내 즉시 수정**과 **라이브러리 제작자에게 제보 전달**을 별도 단계로 유지한다.

## 추천 흐름

1. 학습 중 또는 라이브러리에서 단어를 선택하고 올바른 한국어 뜻과 간단한 설명을 적는다. 내 학습 카드의 뜻은 즉시 수정한다.
2. 제보함에 `미전송`으로 저장하고, 사용자가 **제작자에게 보내기**를 누르면 서버에 전송한다. 오프라인이면 보낼 목록에 남겨 둔다.
3. 서버가 라이브러리의 제작자 ID를 찾아 제보를 해당 제작자의 제보함에 넣는다. 앱 운영자는 전체 제보를 볼 수 있지만, 제작자의 이메일 주소는 제보자에게 공개하지 않는다.
4. 제작자는 `검토 중 → 수락 / 반려`로 처리한다. 수락하면 해당 카드의 원본 데이터를 수정하고 새 라이브러리 버전을 게시한다. 제보자의 로컬 수정은 별도로 보존한다.
5. 제보자는 제보함에서 처리 상태를 확인한다. 알림은 전송 성공과 수락/반려에 한정한다.

제보 데이터에는 `reportID`, `libraryID`, `stackID`, `cardID`, 원래 일본어·읽기·한국어 뜻, 제안한 뜻, 설명, 생성 시각, 라이브러리 버전, 상태를 넣는다. `cardID`를 우선 사용해 같은 표기가 여러 번 나오는 경우에도 정확한 카드를 찾는다. 계정이 없으면 설치별 익명 ID를 사용하고, 답장을 받고 싶은 경우에만 연락처를 선택적으로 받는다. 기기 정보·전체 학습 기록은 보내지 않는다.

## 단계별 구현

- **개인용 첫 단계:** 현재 제보함에 수신인과 제목이 채워진 이메일 작성 또는 시스템 공유 시트를 제공한다. 사용자가 전송을 확정한다. 제작자 연락처가 없으면 앱 운영자에게 보낸다. 메일 작성 화면은 iPhone에 메일 계정이 설정된 경우에만 사용할 수 있으므로 공유 시트를 대안으로 둔다. 작성 화면에서 보내기를 눌러도 최종 수신까지 보장되지는 않아, 앱 상태를 `접수됨`으로 표시하지 않는다. 계정·서버 없이 빠르게 시작할 수 있지만 접수 여부와 처리 상태를 앱에서 확인하기 어렵다.
- **공개 라이브러리 단계:** 서버에 제보 API와 제작자별 제보함을 둔다. 제작자에게 이메일 또는 푸시로 새 제보를 알리고, 앱 운영자도 관리 화면에서 볼 수 있게 한다. 중복 제보 묶기, 전송 제한, 신고 차단, 수락 이력을 적용한다. 제작자 연락처를 앱에 노출하지 않는다.

Google Sheets는 라이브러리의 원본 데이터로 계속 사용할 수 있다. 다만 외부 사용자가 시트에 직접 쓰도록 공유하지 않는다. 서버가 수락된 수정만 검증해 반영하거나, 제작자가 시트에서 직접 수정한 뒤 새 버전을 게시한다. 현재처럼 기기 안의 가짜 서버만 있는 동안에는 다른 기기의 제작자에게 자동 전달할 경로가 없으므로, 첫 단계에서는 명시적인 공유 동작이 필요하다.

소규모 중간 단계로는 별도 비공개 제보 시트에 쓰는 Google Apps Script 웹 앱을 둘 수 있다. 공개 접수 URL을 쓸 경우 스팸 방어와 전송 제한이 필요하며, 단어 원본 시트의 쓰기 권한을 앱에 주지 않는다. 제보가 늘거나 여러 제작자를 지원할 때는 전용 서버와 계정으로 이전한다.
