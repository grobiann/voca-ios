# 세 번, 서로 다른 맥락에서 만나는 단어 — 설계안

구현하지 않은 후속 기능 제안이다. 사용자가 설명한 ‘한 단어의 포스트잇 세 장을 서로 다른 공간에 붙여 세 번 확인한다’는 방식을 앱으로 옮긴다. 특정 암기법의 효과를 검증했다는 의미는 아니다.

## 제안: 오늘의 단어를 세 장면에서 회상하기

새로 배운 단어 중 하루 5개를 골라 세 번의 짧은 만남으로 배치한다. 공간을 GPS로 감지하기보다 사용자가 정한 시간/상황 이름(출근 전, 점심 뒤, 잠들기 전)을 사용한다. 장소를 정하지 않아도 ‘아침·낮·저녁’으로 동작할 수 있다.

| 만남 | 화면과 행동 | 목적 |
| --- | --- | --- |
| 1. 알아보기 | 아침 앱 카드: 일본어를 보고 뜻을 떠올린 후 공개 | 단어와 뜻 연결 |
| 2. 꺼내보기 | 낮 위젯 또는 알림으로 앱 진입: 한국어를 보고 일본어 회상 | 답을 가린 능동 회상 |
| 3. 써보기 | 저녁 앱 카드: 일본어 예문의 빈칸을 채우거나 소리 내어 말한 뒤 자기평가 | 다른 문맥에서 다시 연결 |

초기 제안값은 만남 사이 최소 2시간, 하루 5단어, 사용자 지정 시간대다. 이는 검증된 최적 간격이 아닌 제품 기본값이다. 위젯/알림에서 정답을 바로 노출하지 않고 앱에서 답을 확인한다. 음성인식 자동 채점은 첫 버전에 필요 없다.

## 기존 학습과의 관계

- 현재 ‘스택 완료’는 양방향 정답이라는 의미로 유지한다. 세 번 복습은 별도 ‘정착 기록’으로 표시해 완료한 스택이 갑자기 미완료로 돌아가지 않는다.
- 원래 10장 학습 풀과 오늘의 복습 큐는 분리한다. 같은 단어를 연달아 다른 방향으로 추가하지 않는다.
- 한 만남에서 ‘몰랐어요’이면 짧은 세션 안에서 다시 확인하되, 세 번 복습 중 새 만남으로 세지 않는다. 다음 시간대에도 다시 회상한다.
- 알림 확인, 위젯 노출, 앱 실행만으로 복습 성공 처리하지 않는다. 정답 공개 후 자기평가까지 해야 기록한다.
- 놓친 만남은 실패 표시나 연속 기록 초기화 없이 다음 적절한 시간대로 이동한다. 한꺼번에 세 번 눌러 완료하는 방식은 막는다.
- 세 만남을 마친 뒤 다음날과 일주일 뒤에 짧게 확인하는 확장안을 둘 수 있다. 초기 기능에는 세 만남만 넣어 부담을 확인한다.

## 최소 데이터 모델

`ReviewPlan(wordID, contextLabels, preferredTimes, timezone, enabled)`

`Encounter(wordID, stage, scheduledAt, completedAt, recalled, presentation)`

계획과 실제 응답 기록을 분리한다. 로컬 알림은 해당 기기에서만 예약하고, 시간대 변경이나 일정 수정 시 미래 알림을 다시 만든다. 사용자가 알림을 거부해도 앱 안의 ‘오늘의 세 번’ 목록으로 사용할 수 있어야 한다.

## 이후 선택할 사항

추천 시작점은 **시간대 3개 + 앱 내 회상 + 선택적 알림**이다. 사용해 본 뒤 홈 화면 위젯을 추가한다. 장소 기반 자동 알림, 구독, 음성 채점은 필요가 확인된 이후에 고려한다.

평가할 지표는 연속 출석 수보다 다음날/일주일 뒤 정답률, 복습 소요 시간, 알림 끄기 비율이다. 같은 단어의 단기 반복이 실제 장기 회상으로 이어지는지 비교한다.
